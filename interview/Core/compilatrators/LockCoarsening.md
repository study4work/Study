## Lock Coarsening 
(Расширение блокировок)  
— это JIT-оптимизация, которая объединяет несколько соседних синхронизированных блоков в один более широкий, если между ними нет точек, где другой поток мог бы вмешаться.

Идея: захват и освобождение монитора — это не бесплатно (системные вызовы, барьеры памяти). Если два блока идут подряд и синхронизированы на одном и том же объекте, дешевле захватить монитор один раз на оба блока.

До оптимизации (как написано в коде):
```java
public void updateAccount(Account acc) {
    synchronized (acc) {
        acc.setBalance(acc.getBalance() + 100);
    }
    // Между блоками монитор освобождён — теоретически другой поток 
    // мог бы вмешаться, но JIT видит, что acc локальный и не "сбегает"
    synchronized (acc) {
        acc.setLastUpdated(System.currentTimeMillis());
    }
}
```
После Lock Coarsening (как выполнит JIT):
```java
public void updateAccount(Account acc) {
    synchronized (acc) {  // ОДИН захват на оба блока
        acc.setBalance(acc.getBalance() + 100);
        acc.setLastUpdated(System.currentTimeMillis());
    }
}
```

**Когда применяется**  
JIT применяет Lock Coarsening, когда может доказать, что между блоками нет "точек вмешательства":  
* Объект блокировки один и тот же в обоих блоках.
* Между блоками нет вызовов чужих методов, которые могут захватить другие блокировки.
* Между блоками нет точек, где поток может быть прерван (нет wait(), sleep(), I/O).
* Объект не "сбегает" из метода (иначе другой поток может вмешаться между блоками).
