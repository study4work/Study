## Stream — это ленивый конвейер операций. Он состоит из:
1. Source (источник) — коллекция, массив, генератор
2. Intermediate operations (промежуточные операции) — map, filter, sorted и т.д.
   (Трансформируют, фильтруют или подготавливают элементы потока. Всегда возвращают новый объект Stream. 
   Ленивые (Lazy). Они вообще ничего не вычисляют в момент вызова. Они лишь запоминают операцию и добавляют её в «план» (пайплайн).)
3. Terminal operation (терминальная операция) — collect, forEach, reduce, count
   (Завершают обработку потока, сворачивая его в конечный результат. Именно вызов терминальной операции заставляет 
   JVM пройтись по источнику данных и выполнить все ранее накопленные промежуточные операции.)

**!! После вызова терминальной операции стрим считается потребленным (consumed). Повторно использовать этот же объект Stream нельзя — будет выброшено IllegalStateException.**

## Stateless операции (Без состояния)

Операция, которая обрабатывает каждый элемент независимо от других элементов. Ей не нужно помнить, что было до или после текущего элемента.

Примеры:  
map() — преобразует каждый элемент независимо  
filter() — проверяет каждый элемент независимо  
peek() — выполняет действие для каждого элемента  
flatMap() — преобразует каждый элемент в поток и "сплющивает"

```java
List<String> names = List.of("Alice", "Bob", "Charlie");

List<String> result = names.stream()
    .filter(name -> name.length() > 3)  // Stateless: проверяет каждый name независимо
    .map(String::toUpperCase)            // Stateless: преобразует каждый name независимо
    .collect(Collectors.toList());

// Результат: ["ALICE", "CHARLIE"]
```

Почему это важно: Stateless операции идеальны для параллелизма. Каждый элемент можно обрабатывать в отдельном потоке, не worrying о синхронизации.

## Stateful операции (С состоянием)

Операция, которая должна помнить информацию о других элементах потока, чтобы обработать текущий элемент. Ей нужно "состояние" (state).

Примеры:  
distinct() — должен помнить все встреченные элементы, чтобы отфильтровать дубликаты  
sorted() — должен увидеть ВСЕ элементы, чтобы отсортировать их  
limit() / skip() — должны помнить, сколько элементов уже обработано  
reduce() — накапливает результат (частично stateful)  
collect() — накапливает результат в коллекцию  

```java
List<Integer> numbers = List.of(3, 1, 4, 1, 5, 9, 2, 6, 5);

List<Integer> result = numbers.stream()
    .distinct()  // Stateful: должен помнить все встреченные числа
    .sorted()    // Stateful: должен увидеть ВСЕ числа, чтобы отсортировать
    .limit(3)    // Stateful: должен помнить, сколько элементов уже взял
    .collect(Collectors.toList());

// Результат: [1, 2, 3]
```

Почему это важно: Stateful операции проблематичны для параллелизма. Они требуют синхронизации или буферизации, что убивает производительность.

## Ленивая инициализация (Lazy Evaluation)

Ленивая инициализация — это когда вычисления откладываются до тех пор, пока результат действительно не понадобится.
Они лишь описывают план действий и строят пайплайн.
В Stream API это означает: промежуточные операции не выполняются, пока не вызвана терминальная операция.

## Короткое замыкание (Short-circuiting)
Некоторые терминальные операции (например, findFirst(), anyMatch(), limit()) могут прервать выполнение стрима, как только будет найден нужный результат.  
Преимущество: Если вам нужно найти первый подходящий элемент в коллекции из 10 миллионов записей, 
Stream API остановит перебор на первом совпадении, а не будет обрабатывать весь массив до конца.

## Collector
Это интерфейс в Java, который описывает, как именно нужно накапливать (собирать) элементы стрима в конечный результат (контейнер).   
Он используется в терминальной операции collect().
* supplier(): Создает пустой контейнер для результата (например, новый ArrayList).
* accumulator(): Добавляет очередной элемент стрима в этот контейнер.
* combiner(): Объединяет два контейнера в один. Критически важен для параллельных стримов (.parallel()), 
  так как позволяет независимо собирать части данных в разных потоках, а затем сливать их.
* finisher(): Выполняет финальную трансформацию контейнера перед возвратом результата (например, превращает List в Set или делает коллекцию неизменяемой).

#### Основные методы:  
**toList() / toSet() / toCollection(Supplier) (toCollection(LinkedList::new)) / joining(delimiter) / minBy(comparator) / maxBy()**  
**toMap(keyMapper, valueMapper)**: Собирает стрим в Map. (Осторожно: если ключи дублируются, бросает IllegalStateException, если не передать третий аргумент — функцию слияния).
**groupingBy(classifier)**: Аналог GROUP BY в SQL. Группирует элементы по указанному ключу. Возвращает Map<K, List<V>>. 
Можно комбинировать с другими коллекторами (например, groupingBy(City::getName, counting()) посчитает количество людей в каждом городе).  
**partitioningBy(predicate)**: Делит элементы ровно на две группы по булевому предикату. Возвращает Map<Boolean, List<V>>, где ключи — это true и false.  
**collectingAndThen(collector, finisher)**: Позволяет применить финальную операцию к результату. 
Классический пример: collectingAndThen(toList(), Collections::unmodifiableList) — собирает список и сразу делает его неизменяемым.

## Можно ли изменять состояния внешних переменных в Stream  
* **Переприсваивание ссылки (Нельзя)**: Переменные из внешнего контекста, используемые внутри лямбда-выражений, 
  должны быть effectively final (фактически финальными). Вы не можете написать count++ или list = new ArrayList<>() 
  внутри стрима — компилятор просто не соберет такой код.
* **Изменение состояния объекта (Можно, но опасно)**: Если внешняя переменная ссылается на мутабельный (изменяемый) 
  объект (например, List, Map, StringBuilder или кастомный DTO с сеттерами), вы можете менять его внутреннее состояние (например, myList.add(...)).

## Side Effects  
Примеры побочных эффектов:
* Изменение внешней переменной или поля класса.
* Мутация исходной коллекции, по которой идет итерация.
* Ввод/вывод: запись в файл, логирование (System.out.println), отправка сетевого запроса.
* Бросание исключений (в некоторых контекстах).  

Идеальная лямбда в Stream API (чистая функция) должна зависеть только от своих входных данных и не менять ничего вовне.

**Изменение внешних переменных**
```java
// ❌ Плохо
stream.forEach(item -> {
        externalList.add(item); // Сайд-эффект
});
// ✅ Хорошо
List<Result> result = stream.map(item -> transform(item))
        .collect(Collectors.toList());
```

**Изменение объектов вне стрима**
```java
// ❌ Плохо
int[] counter = {0}; // Внешний счетчик

stream.forEach(item -> {
    counter[0]++; // САЙД-ЭФФЕКТ: изменяем внешнюю переменную
    process(item);
});
// ✅ Хорошо
long count = stream.count();
```
**I/O операции (вывод, логирование)**
```java
// ❌ Плохо
stream.map(s -> {
    System.out.println(s); // Сайд-эффект: вывод в консоль
    return s.toUpperCase();
});
// ✅ Хорошо
stream.peek(System.out::println) // peek() для отладки
      .map(String::toUpperCase);
```
**Изменение состояния объектов**
```java
// ❌ Плохо
stream.forEach(user -> user.setActive(true)); // Сайд-эффект: изменяем объекты
// ✅ Хорошо
stream.map(user -> new User(user.getId(), user.getName(), true)) // Создаем новые объекты
.collect(Collectors.toList());
```
