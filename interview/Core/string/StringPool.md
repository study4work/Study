## String Pool   
— это кэш-таблица в куче (Heap),  
где JVM хранит по одному экземпляру каждой уникальной строки,  
чтобы не дублировать одинаковые строки в памяти.

При создании строки через литерал JVM проверяет пул:  
если строка есть — возвращает существующую ссылку, если нет — создаёт новый объект в пуле.  
При создании через new объект всегда создаётся в куче отдельно от пула

**Ключевая идея**: если одна и та же строковая последовательность   
встречается в программе много раз, в пуле хранится только один  
экземпляр, а все переменные ссылаются на него.

StringPool хранится в Metaspace c Java8+(сам Metaspace находится в Heap)  
Литералы ссылаются на один и тот же объект в Heap  
(_Почему перенесли с версии 6? В PermGen строки из пула не могли быть собраны   
сборщиком мусора, что приводило к OutOfMemoryError: PermGen space  
при большом количестве интернированных строк. В Heap они стали   
доступны для GC._)

**Логика intern()(ручное добавление в пул)**:  
Ищет строку в пуле.  
Нашёл → возвращает ссылку из пула.  
Не нашёл → добавляет объект в пул и возвращает ссылку.  

**! intern() стоит использовать только для строк которые живут долго и повторяются много раз**:  
статусы, категории, названия стран, типы событий.  
Для уникальных строк (UUID, email, timestamp) он вреден, потому что раздувает пул без какой-либо экономии памяти.
