## BlockingQueue<E>
интерфейс из пакета java.util.concurrent, представляющий очередь, которая блокирует потоки при попытке:
* взять элемент из пустой очереди (поток ждёт, пока кто-то положит элемент);
* положить элемент в полную очередь (поток ждёт, пока кто-то возьмёт элемент).  
Это основа паттерна producer-consumer (производитель-потребитель).

Для пулов потоков критичны методы put()/take() и offer(..., timeout) — они позволяют потокам-работникам корректно ждать задачи.

Основные реализации:
1. **ArrayBlockingQueue(int capacity)**
* Ограниченная очередь на основе массива.
* Честная (fair) — потоки обслуживаются в порядке FIFO (если включён fair mode).
* Используется, когда нужно контролировать размер и применять back pressure.
* Классический выбор для ThreadPoolExecutor с ограниченной очередью.

2. **LinkedBlockingQueue()**
* Может быть ограниченной (LinkedBlockingQueue(capacity)) или неограниченной (по умолчанию Integer.MAX_VALUE).
* Неограниченная очередь = Executors.newFixedThreadPool() — задачи никогда не отклоняются, но могут переполнить память (OOM).
* Две независимые блокировки (на голову и хвост) → выше пропускная способность.

3. **PriorityBlockingQueue**
* Неограниченная очередь с приоритетами (по Comparable или Comparator).
* Задачи с высоким приоритетом выполняются первыми.

4. **SynchronousQueue**
* Нулевая ёмкость — каждый put() блокируется, пока другой поток не сделает take().
* Нет буферизации — прямая передача задачи от producer к consumer.
* Используется в Executors.newCachedThreadPool() — создаёт новый поток по требованию.

5. **DelayQueue**
* Элементы можно забрать только после истечения задержки (Delayed).
* Применяется для отложенных задач, таймеров, повторных попыток.

Применение в пулах потоков
```java
ThreadPoolExecutor:
├── corePoolSize        — минимальное число потоков
├── maximumPoolSize     — максимальное число потоков
├── workQueue           — BlockingQueue<Runnable> — очередь задач
├── threadFactory       — фабрика потоков
└── rejectedHandler     — политика при переполнении
```
Связь очереди и политик насыщения (RejectedExecutionHandler)

Политика срабатывает, когда и очередь полна, и достигнуто maximumPoolSize:  
* AbortPolicy (по умолчанию) — бросает RejectedExecutionException.
* CallerRunsPolicy — задача выполняется в потоке-вызывателе (back pressure).
* DiscardPolicy — задача молча отбрасывается.
* DiscardOldestPolicy — отбрасывается самая старая задача в очереди.
