### LongAdder 
— это класс из пакета java.util.concurrent.atomic, появившийся в Java 8. Он решает главную проблему AtomicInteger: падение производительности при высокой конкуренции (когда много потоков одновременно пытаются инкрементировать один и тот же счетчик).

**LongAdder использует идею:**  
вместо одного общего счетчика создать много ячеек (cells), и каждый поток инкрементирует свою ячейку.

```java
LongAdder counter = new LongAdder();

// 100 потоков одновременно делают:
counter.increment();
```

Что происходит под капотом:  
* LongAdder создает массив ячеек (например, на 16 или 64 элемента).
* Каждый поток хешируется (по ID потока или другим признакам) и попадает в свою ячейку.
* Поток 1 инкрементирует ячейку №3.
* Поток 2 инкрементирует ячейку №7.
* Поток 3 инкрементирует ячейку №3 (если хеш совпал).
* Конкуренция минимальна, потому что потоки редко попадают в одну ячейку.  

Когда нужно получить итоговое значение:
```java
long total = counter.sum(); // Суммируем ВСЕ ячейки
```

Аналогия: Вместо одного турникета (AtomicInteger) открываем 16 турникетов (LongAdder). Люди распределяются по ним равномерно. Каждый проходит быстро. В конце дня считаем: "Сколько всего прошло через все турникеты?" — суммируем показания каждого.

### Важные нюансы LongAdder
1. sum() не атомарен  

**Проблема**: sum() проходит по всем ячейкам и суммирует их. Если в этот момент другой поток инкрементирует одну из ячеек, sum() может вернуть значение, которое никогда не существовало в реальности (например, "было 10, стало 11, а sum() вернул 10.5").  
**Когда это критично**: Если тебе нужна строгая согласованность (например, баланс банка), используй AtomicInteger или synchronized.  
**Когда это нормально**: Если ты собираешь статистику (сколько запросов обработано за час), небольшая неточность не важна.
