Механизм прерываний (Interruption) в Java — это кооперативный способ остановки или отмены выполнения потока.

В отличие от устаревших и опасных методов Thread.stop() или Thread.suspend(), которые насильно убивали поток и   
могли привести к блокировкам или повреждению данных, механизм interrupt() ничего не делает с потоком напрямую.   
Он лишь выставляет внутренний boolean-флаг в объекте Thread. Пот сам должен периодически проверять этот флаг и решать,  
как ему корректно завершить свою работу.

#### Как это работает: 3 главных метода
1. thread.interrupt()  
Устанавливает флаг прерывания в true. Если поток в данный момент находится в состоянии ожидания (спит, ждет монитор, заблокирован на прерываемом канале), JVM выбросит в нем InterruptedException и сбросит флаг в false.
```
interrupt() — это кооперативный запрос на отмену: он выставляет потоку флаг и, если поток стоит в прерываемой блокировке, 
немедленно выбивает его оттуда через   InterruptedException. Поток сам решает, как отреагировать: корректно свернуть работу, 
освободить ресурсы и вернуть управление. В пуле потоков это означает завершение   задачи, а не воркера — 
ThreadPoolExecutor сбрасывает флаг перед следующей задачей и переиспользует тот же Thread. 
Насильственного убийства потока не происходит, поэтому инварианты данных не ломаются.
```
```java
public class CalculationTask implements Runnable {
    @Override
    public void run() {
        // Проверяем флаг прерывания в условии цикла
        while (!Thread.currentThread().isInterrupted()) {
            // Делаем какую-то тяжелую работу
            System.out.println("Вычисляю...");
            try {
                Thread.sleep(500); // Имитация работы
            } catch (InterruptedException e) {
                // Если поток спал, при вызове interrupt() вылетит исключение.
                // Флаг при этом сбросится в false, поэтому нужно либо выйти,
                // либо восстановить флаг (см. Best Practices).
                System.out.println("Меня прервали во время сна!");
                break; // Выходим из цикла
            }
        }
        System.out.println("Поток корректно завершил работу.");
    }

    public static void main(String[] args) throws InterruptedException {
        Thread thread = new Thread(new CalculationTask());
        thread.start();
        
        Thread.sleep(2000); // Даем поработать 2 секунды
        System.out.println("Отправляем запрос на прерывание...");
        thread.interrupt(); // Выставляем флаг
    }
}
```
2. thread.isInterrupted()  
Нестатический метод. Проверяет статус флага. Возвращает true или false. Не сбрасывает флаг.
3. Thread.interrupted()  
Статический метод. Проверяет статус флага текущего потока. Важная особенность: сбрасывает флаг в false после проверки.


**В каких случаях нужно использовать прерывания?**  
* Graceful Shutdown (Плавное завершение): Когда приложение (например, Spring Boot или Tomcat) получает сигнал на остановку (SIGTERM), оно вызывает interrupt() у всех рабочих потоков, чтобы они закрыли ресурсы, сохранили данные и завершились.
* Отмена задач в пулах потоков: При использовании ExecutorService и Future, вызов future.cancel(true) внутри вызывает interrupt() у потока, выполняющего задачу.
* UI-приложения: Если пользователь нажал кнопку "Отмена" при загрузке файла, фоновый поток должен быть прерван, чтобы не тратить ресурсы.
* Таймауты: Если операция занимает слишком долго, внешний наблюдатель может прервать поток, чтобы вернуть управление пользователю.
