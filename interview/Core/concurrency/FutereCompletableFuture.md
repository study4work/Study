CompletableFuture реализует интерфейс Future, но добавляет к нему возможность строить неблокирующие цепочки вызовов, комбинировать задачи и обрабатывать ошибки в функциональном стиле.

##### **Future**:   

Чтобы получить результат, нужно вызвать метод get(), который блокирует текущий поток до тех пор, пока задача не выполнится.  
Исключения "прячутся" внутри Future. При вызове get() вы получите ExecutionException, а реальную причину придется доставать через getCause(). Приходится использовать try-catch.

##### **CompletableFuture**:  

Позволяет навешивать коллбэки (функции обратного вызова), которые сработают автоматически, когда результат будет готов. Поток не блокируется.  
Позволяет обрабатывать ошибки декларативно, не прерывая цепочку:  

#####  **exceptionally**() — что делать, если произошла ошибка (аналог catch).  
#####  **handle**() — срабатывает в любом случае (и при успехе, и при ошибке). Принимает и результат, и исключение. Позволяет трансформировать результат.  
#####  **whenComplete**() — выполнить действие в любом случае (аналог finally).  

**Когда использовать Future:**  
* Простая асинхронная задача — нужно запустить и забрать результат.
* Работа с legacy-кодом — старые API возвращают Future.
* Минимальные зависимости — не нужен весь API CompletableFuture.
* Контроль над пулом потоков — явно указываешь ExecutorService.  

**Когда использовать CompletableFuture:**  
* Цепочки асинхронных операций — результат одного шака передаётся в следующий.
* Параллельное выполнение нескольких задач — allOf(), anyOf().
* Неблокирующие колбэки — не хочешь блокировать поток через get().
* Обработка ошибок в конвейере — централизованная обработка через exceptionally().
* Реактивные паттерны — комбинация с Stream API, асинхронные конвейеры.

# Future vs CompletableFuture

| Аспект                 | Future                 | CompletableFuture                |
|------------------------|------------------------|----------------------------------|
| **Создание**           | Только через Executor  | Вручную: `complete(value)`       |
| **Колбэки**            | ❌ Только `get()`      | ✅ `thenApply()`, `thenAccept()` |
| **Цепочки**            | ❌ Вложенные `get()`   | ✅ `thenCompose()`, `thenApply()`|
| **Комбинирование**     | ❌ Вручную             | ✅ `allOf()`, `anyOf()`          |
| **Ошибки**             | ❌ try-catch           | ✅ `exceptionally()`, `handle()` |
| **Блокировка**         | `get()` throws checked | `get()` + `join()` (unchecked)   |
| **Пул**                | Executor явно          | `ForkJoinPool.commonPool()`      |
| **Без блокировки**     | ❌ Нет                 | ✅ `getNow(value)`               |

**Когда использовать:**
- **Future** — простые задачи, legacy-код, явный контроль Executor
- **CompletableFuture** — цепочки операций, параллелизм, реактивный стиль

**Ключевые отличия:**
1. Future блокирует поток через `get()`, CompletableFuture — неблокирующие колбэки
2. CompletableFuture поддерживает композицию (`thenCompose` = flatMap)
3. CompletableFuture использует `ForkJoinPool.commonPool()` по умолчанию
4. В CompletableFuture ошибки оборачиваются в `CompletionException`
