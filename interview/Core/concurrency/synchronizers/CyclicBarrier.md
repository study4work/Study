## CyclicBarrier

— циклический барьер
N потоков ждут друг друга в одной точке. Когда все пришли — все идут дальше. Можно использовать повторно (в отличие от latch).

```java
int threadCount = 4;
CyclicBarrier barrier = new CyclicBarrier(threadCount, () -> {
    /* Выполняется один раз после прихода всех, до их разблокировки */
    mergePhaseResults();
    System.out.println("Фаза завершена, начинаем следующую");
});

for (int i = 0; i < threadCount; i++) {
final int id = i;
    executor.submit(() -> {
        try {
        while (!isDone()) {
        computePartialResult(id);
        barrier.await(); // ждём остальных
/* mergePhaseResults() уже выполнен */
            }
        } catch (BrokenBarrierException | InterruptedException e) {
        Thread.currentThread().interrupt();
        }
    });
}
```
1. Параллельная работа: 4 потока независимо и одновременно вычисляют свою часть задачи (computePartialResult).
2. Точка ожидания: Закончив свой кусок работы, каждый поток останавливается на barrier.await() и ждет, пока остальные 3 тоже закончат.
3. Единая сборка: Как только все 4 потока собрались, последний пришедший поток единолично выполняет код барьера (mergePhaseResults). Остальные в этот момент всё еще заблокированы и ждут.
4. Автоматический перезапуск: После завершения сборки барьер мгновенно "открывается", все 4 потока одновременно просыпаются и переходят к следующей итерации цикла (while). Барьер готов к использованию снова.
5. Защита от зависания: Если один из потоков упадет с ошибкой или будет прерван, барьер "сломается" (BrokenBarrierException), и остальные потоки не будут ждать вечно, а корректно завершат работу.

Сценарий: параллельные вычисления с фазами (например, матричные операции).
