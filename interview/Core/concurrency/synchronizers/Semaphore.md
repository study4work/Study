## Semaphore
—  счётчик разрешений. Это не лок, а счётчик разрешений. Представьте парковку на 5 мест — семафор с permits=5.

НЕ реализует Lock (нет reentrancy!)  
Задача: ограничить число потоков, одновременно работающих с ресурсом  
Состояние: int-счётчик разрешений

```java
Semaphore semaphore = new Semaphore(3);  // 3 разрешения

public void accessResource() throws InterruptedException {
    semaphore.acquire();   // запросить разрешение (если 0 — ждать)
    try {
        // работаем с ресурсом (не более 3 потоков одновременно)
    } finally {
        semaphore.release();   // вернуть разрешение
    }
}
```

## 1. Справедливость (Fairness)
По умолчанию семафор несправедлив (Non-fair). Это значит, что когда освобождается разрешение, его может получить любой ждущий поток (не обязательно тот, кто ждет дольше всех). Это дает максимальную производительность.  
Если нужен строгий порядок (FIFO), его можно включить:  
```java
Semaphore semaphore = new Semaphore(3, true); // true = fair
```
## 2. tryAcquire() — защита от вечного ожидания
Вместо блокирующего acquire() лучше использовать неблокирующие варианты, чтобы избежать дедлоков или долгих простоев:
```java
// Попытаться взять разрешение, ждать не более 1 секунды
if (semaphore.tryAcquire(1, TimeUnit.SECONDS)) {
    try { /* работа */ } 
    finally { semaphore.release(); }
} else {
    // Разрешения нет, идем делать что-то другое или возвращаем ошибку клиенту
}
```

ReentrantLock (и обычный synchronized) запоминает, какой именно поток захватил блокировку. Этот поток становится "владельцем" (owner). Разблокировать (unlock()) этот замок может только поток-владелец. Если другой поток попытается это сделать, он получит IllegalMonitorStateException.  
Semaphore не знает и не запоминает, кто взял разрешение. Для него есть только счетчик. Разрешение может взять Поток А, а вернуть (вызвать release()) — Поток Б. И семафору будет всё равно.
