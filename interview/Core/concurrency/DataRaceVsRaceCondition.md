### Race Condition
Суть: Результат работы программы зависит от того, в каком порядке потоки выполняют свои операции. Это логическая ошибка, даже если каждый поток работает правильно сам по себе.  

### 1. Check-Then-Act (Проверь, затем действуй)
   Суть: Поток проверяет какое-то условие, и если оно истинно, выполняет действие. Но между проверкой и действием данные могут измениться другим потоком.  
```java
// Поток А и Поток Б выполняют это одновременно
if (!map.containsKey(key)) {       // ШАГ 1: ПРОВЕРКА (Check)
    // [ЗДЕСЬ МОЖЕТ ПРОИЗОЙТИ ПЕРЕКЛЮЧЕНИЕ ПОТОКА!] 💥
    map.put(key, value);           // ШАГ 2: ДЕЙСТВИЕ (Act)
}
```

**Что идет не так**:  
Оба потока видят, что ключа нет. Оба заходят внутрь if. В итоге в карту записывается только одно значение (или происходит потеря данных), хотя логика подразумевала, что запись будет уникальной.  
**Как лечить**:  
Сделать проверку и действие единой неделимой (атомарной) операцией.
* В ConcurrentHashMap для этого есть метод putIfAbsent(key, value).
* Или обернуть оба шага в один блок synchronized.

### 2. Read-Modify-Write (Прочитай, измени, запиши)
   Суть: Поток читает текущее значение переменной, изменяет его у себя (в регистре процессора), и записывает новое значение обратно в память.
```java
// Поток А и Поток Б выполняют это одновременно
int temp = counter;                // ШАГ 1: ПРОЧИТАТЬ (Read)
temp = temp + 1;                   // ШАГ 2: ИЗМЕНИТЬ (Modify)
counter = temp;                    // ШАГ 3: ЗАПИСАТЬ (Write)
// (В Java это всё скрыто за одной операцией: counter++)
```   
**Что идет не так:**   
* Поток А читает counter (там 0).  
* Поток Б читает counter (там всё еще 0, так как А еще не записал).  
* Поток А вычисляет 0 + 1 = 1 и записывает 1.   
* Поток Б вычисляет 0 + 1 = 1 и записывает 1.  
Итог: Было два инкремента, а значение увеличилось только на 1. Это называется потерянное обновление (Lost Update).  

**Как лечить**:  
Использовать атомарные операции, которые выполняются на уровне процессора за один такт.  
Использовать AtomicInteger и его метод incrementAndGet().  
Использовать synchronized.  
Использовать методы вроде compute() или merge() в ConcurrentHashMap.  

### Data Race — "Проблема доступа к памяти"
**Суть**: Несколько потоков одновременно обращаются к одной переменной, и хотя бы один из них пишет в неё, без использования синхронизации. Это нарушение правил Java Memory Model.

**Проблема**: Ты читаешь данные, которые меняются прямо сейчас, без синхронизации. Процессор может кэшировать значения, компилятор может переупорядочивать операции, и ты видишь устаревшие или некорректные данные.

```java
// Поток 1
public void writer() {
    counter++;  // Запись без синхронизации 💥 Data race!
}

// Поток 2
public void reader() {
    int value = counter;  // Чтение без синхронизации 💥 Data race!
}
```
